# 制限事項と未実装範囲

## 動作確認の境界

実SDKを取得できない環境で作成しています。実際のDxLibヘッダーとのコンパイル、MSVCのABI・ランタイム・ライブラリ選択、Windows専用エントリーポイント、描画・音声・デバイス動作は未確認です。手書きの代替ヘッダーは、宣言やABIの正しさを保証するものではありません。

公開ヘッダー、SandboxGame.cpp、NativeSmoke共通コードは実際にコンパイルしていますが、WindowsMain.cppはLinuxのビルド対象ではありません。Windows用PowerShellとCIは実行していません。SDKやドライバーの差に起因する修正が必要になる可能性があります。

## 機能の範囲

この版は2D画像・矩形・文字と、Scene／GameObject／Componentの実行基盤です。3Dモデル、カメラシステム、アニメーション編集、衝突・物理、セーブ、エディター、非同期ロード、ホットリロード、固定ステップ物理、DLLプラグインは提供していません。Sceneは同時に1つを有効にする構成で、Sceneスタックや複数Sceneの重ね合わせは未実装です。

日本語のパス・ウィンドウ名・文字はUTF-8で渡す実装ですが、実際のフォント表示と日本語パスはWindowsで確認が必要です。IMEテキスト入力、右スティック、トリガー、標準化されたゲームパッドボタン名は未実装です。InputMapはキーボード・マウス・Padのデジタルボタンに対応します。

RenderTargetの任意アルファクリア、DxLibの全描画状態の保存・復元は未対応です。対応範囲は[API](API.md)を参照してください。NativeのSoundLoaderはロード後の音声生成設定をMEMNOPRESSへ戻します。外部で設定した別の値を自動で復元するものではありません。

## 性能・メモリ

安全性と責務分離を優先した実装です。Storageへの挿入は空きスロットを線形探索し、更新・描画ではスナップショットを作り、更新順にソートします。大規模なECSや数十万Objectの性能を保証する構成ではありません。必要な規模で計測してから、空きリストやスナップショット再利用などへ差し替える前提です。

Scene切り替えの準備中は、新旧両方のSceneと資源が生存します。非同期に準備するわけではないため、重い読み込み中はメインスレッドが止まります。

## 利用上の契約

内部APIを自由に呼び、Containerの確定中に直接破棄する使い方は対象外です。ハンドルから一度取得した生ポインタを破棄境界の後まで保持してはいけません。別のバックエンドの資源をRendererへ渡す用途も対象外です。

この版はメインスレッド専用で、スレッドセーフなフレームワークではありません。共有参照の参照カウントが安全であることと、DxLib操作を複数スレッドから行えることは別です。

不正アクセスがテストで見つからなかったことは、不具合が存在しない証明ではありません。テスト・サニタイザーが実行していない経路や実機依存の問題は残り得ます。

## ビルドと配布

C++20、標準RTTIとC++例外を必要とします。Unrealのビルド設定をそのまま移植するものではありません。実SDKを使うターゲットはWindows／MSVC／x64に限定しています。

install／find_packageはソース互換の0.2系パッケージとして提供し、ビルド設定ごとの静的ライブラリを使用します。異なるMSVC・CRT・コンパイラ間のABI互換性や、DLLとしての安定ABIは保証していません。

NativeSmokeは正常時12フレームで終了するAPI検査です。DxLib内部で停止した場合にC++側だけで中断を保証するものではありません。CTestへ登録する場合のタイムアウトは60秒です。
