# FBX読み込みの対応範囲

標準経路は`.fbx → ufbx → メモリ上のDirectX .x → DxLib`です。
利用者による`.mv1`への事前変換とAutodesk FBX SDKは不要です。
DxLib本体のFBXローダーを有効にする方式とは区別します。

## 現在の扱い

| データ | 扱い |
|---|---|
| メッシュ、法線、基本拡散色、拡散テクスチャ | 対応。多角形は三角形化、欠落法線は生成 |
| 線形・剛体スキン、骨階層、ノードのアニメーション | 対応。行列キーへ標本化し、短いクリップも終端を含める |
| モーフ | 1チャンネル1ターゲットの位置・法線差分、複数モーフ、スキンとの併用、変形量のアニメーションと個体別の手動上書きに対応。中間ターゲット・頂点別重み付き差分は拒否 |
| 追加UV | 合計2組まで最終ネイティブ頂点へ保持。3組以上は失敗。標準の拡散描画はUV0を使用し、UV1は追加シェーダー用 |
| 頂点カラー | 最初の色セットに対応。RGBAと材質拡散色を読み込み時に乗算し、GPUで補間。DxLibの8ビット精度。積が非有限または0〜1の範囲外なら失敗 |
| PBR・未知の材質 | 警告付きの部分読み込み。既存のFBX拡散色とベーステクスチャへの代替だけを使う。PBRの見た目は再現しない |
| Phongの鏡面色・光沢・自己発光 | 警告して省略。拡散色・テクスチャだけを使う |
| ファイル内のカメラ／ライト | 静止時の透視・正射影カメラと指向性・点・スポットライトを取得し、ビューへ明示適用。光源は1ビュー1個。面・体積光と影は警告して省略、アニメーションは未適用 |
| 複数スキン、Dual Quaternion方式、拘束による変形 | 明示的な失敗。先に制作ツールで対応する骨変形・キーへ焼き込む |
| 破損、空入力、FBX以外の形式、無効な設定、過大なアニメーション | 明示的な失敗 |
| 読めない外部テクスチャ | ネイティブ側で警告し、DxLibの代替画像で読み進める。テクスチャが正常に読めた扱いにはしない |

未対応機能は将来の追加対象です。この表は現在の実装の契約であり、今後も対応しないという宣言ではありません。
部分読み込みで全情報を保持したと解釈しないでください。任意の制作ツールの全FBXを保証するものではありません。

頂点色のあるフレームだけ、材質ごとに分かれた全ネイティブメッシュで色を有効にします。色のないモデルの材質設定は変更しません。
中間データの`MeshVertexColors`は、DxLibの区切り付き`IndexedColor`解析に合わせて0〜255で出力します。一般の.xリーダー向けの書き出しAPIではありません。

## 警告と失敗の取得

`ImportFbxModel()`は失敗を`TResult`で返し、成功時の`FImportedModel::Warnings`に省略した機能とufbxの回復可能な問題を残します。
`FAssetService::LoadModel()`経由では`DXF_LOG_WARNING`にも出力します。
`FModel::GetImportWarningCount()`と`GetImportWarning(Index)`から読み返せます。キャッシュから取得しても警告は残ります。
`GetImportWarning`の範囲外はnullptrです。返された文字列へのポインターはモデルの生存中だけ有効です。

## セットアップ独立性

2026-09-23時点で、この作業に利用可能な別のWindows環境は確認できていません。
現在のPCにはAutodesk FBX SDKがインストールされています。
今回使うDxLibのマニフェストは`with_fbx=false`、`fbx_sdk_root`と`fbx_sdk_version`は空で、リンクにFBX SDKを含めません。
これは**SDKを参照しない構成の確認**であり、**SDKを一度も導入していない環境での確認ではありません**。

未導入環境でのソースZIPからのSetup、Debug／Releaseビルド、実モデル読込・描画、外部利用は引き続き未検証です。
比較用SDKのアンインストールや過去ZIPの再適用で、この条件を満たしたものとは扱いません。

## 基本材質とモデル照明

`FModelInstance::SetMaterial(FModelMaterial3D)`で、インスタンスごとの不透明な色倍率と`bLit`を指定できます。
初期値は白・照明なしで既存の描画を保ちます。`Tint.A`が255以外なら設定を拒否し、以前の値を保ちます。
描画を受け付けた時点の材質を保存するため、その後の変更は記録済みの描画へ遡及しません。

`bLit=true`は、現在の`FRenderView3D`の指向性光・環境光をDxLibのモデル用照明へ渡します。
CPU基本形状は従来どおりCPUで面単位に照明を計算し、二重に照明を掛けません。
`Unlit`の調査表示は照明なし、`LightsOff`は黒として描画します。
照明用ハンドルは必要になったビューで一度だけ作成し、そのビューのモデル間で再利用します。
外部ライトの有効状態は一時保存してモデルビューから分離し、終了・失敗時に復元します。
描画後は2D用の標準状態へ戻します。任意のネイティブ状態全体を保存するAPIではありません。
DxLibのグローバル環境光を外部コードで変更した場合の合成はDxLibの仕様に従い、この機能ではその設定を変更しません。

これは基本的な拡散照明です。PBRや影を実装済みとするものではありません。

## ソース版DxLibの追加UV拡張

`.x`の基本データに加えて`FImportedModel::MeshExtensions`をモデル確定前へ渡します。
公式ソースは変更せず、ビルド先に生成した2ファイルへ、対象を照合した小さい変更を適用します。
既存UV0の描画とスキンを保ち、UV1の継ぎ目を含めて頂点を共有判定します。
通常のUV0だけのモデルでは追加UV配列を確保しません。
拡張のないDxLibに追加属性を渡した場合はSetupの再実行が必要という失敗を返します。
`DxLibFbx.json`の`model_extension_version=1`で接続の有無を識別します。
モデルは同期で読み込む必要があり、DxLib側の非同期読込フラグが立っていれば拒否します。

現時点でUV1の保持と実モデル描画は検証済みですが、任意のFBX材質のUV選択・複数テクスチャ合成を再現する段階ではありません。

## モーフの利用と現在の制限

`FModel::GetMorphCount()`、`GetMorph()`、`FindMorph()`で名前と番号を取得できます。
`FModelInstance::SetMorphWeight(Index, Weight)`で0〜1の変形量を手動指定し、`ResetMorphWeight(Index)`でクリップまたはファイルの初期値へ戻します。
`Play()`、`SetTime()`、`Advance()`、`Pause()`は骨とモーフの両方に適用されます。
描画を受け付けた時点の変形量を保存し、複製インスタンスの変更を共有しません。

モデル拡張は`model_extension_version=2`が必要です。SDKを更新した場合はフレームワークと利用側を再ビルドしてください。
形状差分を読み込み時に渡し、再生時は変形量だけを更新します。形状の再読み込みは行いません。
変形処理はDxLibの既存シェイプ処理を使い、**GPUモーフを実装したという意味ではありません**。
法線差分がないファイルは警告して基本法線を保ちます。
1チャンネルに複数の中間ターゲットがある形状、負の目標重み、頂点別重み付き差分、0〜1を超える変形量は明示的に拒否します。
差分の展開は合計400万頂点、モーフのアニメーション標本は合計100万に制限します。

## ファイル内カメラ・ライトの利用

`FModel::GetCameraCount()/GetCamera()`と`GetLightCount()/GetLight()`から、接続されたノードごとの静止情報を取得します。
位置・距離はモデルと同じ左手系Y上向き・指定単位です。共有モデルから取得した情報だけでは描画状態を変更しません。
`Camera->ApplyTo(View)`でカメラを、`Light->ApplyTo(View, Range, Attenuation)`でモデル用ライトを選択します。
選んだ1個のライトをそのビュー内の照明ありモデルで共有し、外部ライトは以前と同様に分離・復元します。
点光源とスポット光もDxLibのGPUモデル照明で処理します。CPU基本形状は従来の指向性光のままです。

ライトのRGBは強度を含めた浮動小数点で保持します。`Range`はワールド単位、`Attenuation`は定数・距離・距離二乗の係数です。
FBXの減衰方式・光量単位をDxLibへ完全換算する契約ではなく、減衰のある入力では警告し、アプリから係数を指定します。
既定係数は`{1,0,0}`です。無効な設定は適用先を変えず失敗します。
正射影はファイルの縦の大きさを使い、透視は垂直画角を使います。縦横比は描画先に従い、元の比率は`AspectRatio`で取得できます。
フィルムのずれ、独立したRollプロパティ、注視対象、カメラ／ライトのアニメーションは再現せず警告します。
モデルインスタンスの変換は静止情報に自動適用しません。利用側でワールド配置を変えた場合は、取得情報も必要に応じて変換してください。
