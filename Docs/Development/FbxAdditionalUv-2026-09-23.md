# 追加UVの接続（2026-09-23）

ufbxで合計2組までのUVを取り出し、追加UVの継ぎ目も頂点共有判定へ含める。
UV0だけのモデルでは追加UV配列を確保しない。
DxLibのソース版ビルドは公式ソースを直接変更せず、ビルド先のコピーへ次の2点を追加する。
- .xの解析後、ネイティブモデル確定前に追加属性を受け取る。
- UV1を持つモデルは、拡散テクスチャが1枚でも最終頂点に2組のUVを保持する。

拡張のないライブラリは追加属性付きモデルを明示的に拒否する。追加データを無視して読み込み成功にはしない。
マニフェストのmodel_extension_version=1と拡張ソースのSHA-256で構成を記録する。
第三者SDKやビルド済みライブラリをGitへ追加しない。

今回の確認:
- Debug / ReleaseのCTest各23/23成功。追加UVの継ぎ目を分離する回帰と旧ライブラリの明示的拒否を含む。
- 実DxLibの参照頂点からUV0とUV1の対応式を検査し、最終頂点での保持を確認。
- 2組のUVを持つモデルの実描画、既存モデルの照明・色・独立再生も成功。
- Toolsの19テストと、配布物・外部利用の7段階検証が成功。
- ログはBuild/FbxContinuation/uv-*とextension-*。SDK未導入環境の検証ではない。
標準材質はUV0を使い、UV1の保持だけでは任意の複数テクスチャ合成を再現しない。
非UV0を指定した拡散テクスチャは、この制限を警告する。
